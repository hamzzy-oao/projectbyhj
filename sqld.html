내 선택: 모름 정답: ①
💡 개발자 눈높이 해설 (출제자 함정 & 원리)
DML(데이터 조작)은 테이블 안의 '데이터 행'을 다루는 쿼리(SELECT, INSERT, UPDATE, DELETE)입니다. DDL(구조 정의: CREATE, ALTER, DROP, RENAME), DCL(권한 제어: GRANT, REVOKE), TCL(트랜잭션: COMMIT, ROLLBACK)과 엄격히 구분됩니다.
👶 10살도 이해하는 한 줄 비유

⚡ 시험장 1초 컷 공식 (치트키)
DML = S-I-U-D (SELECT, INSERT, UPDATE, DELETE). SELECT도 데이터를 '조회'하는 DML에 속합니다!

문제 45번 · WHERE절과 집계함수
2과목 SQL 기본 및 활용 · 1장 SQL 기본 · 8번
틀림 GROUP BY
SQL 문을 실행했을 때 오류가 발생하는 부분으로 가장 적절한 것은?
  • ① SELECT DEPTNO, ROUND(AVG(SAL),2)
  • ② FROM EMP
  • ③ WHERE AVG(SAL) >= 1800
  • ④ GROUP BY DEPTNO;
내 선택: ② 정답: ③
💡 개발자 눈높이 해설 (출제자 함정 & 원리)
SQL의 실행 순서는 `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`입니다. WHERE절은 그룹화(GROUP BY)를 하기 전에 개별 행을 필터링하는 단계이므로, 그룹 전체의 평균을 구하는 `AVG()`, `SUM()` 같은 집계함수를 절대로 쓸 수 없습니다. 집계 결과 필터링은 반드시 `HAVING`에 써야 합니다.
👶 10살도 이해하는 한 줄 비유
반별 평균 점수(AVG)를 계산하기도 전에, 반도 안 나눈 상태(WHERE)에서 '평균 80점 이상인 반 나와' 할 수는 없어요. 먼저 반을 묶고(GROUP BY), 그 다음 평균을 따져야(HAVING) 해요.
⚙️ 단계별 실행 과정 (Step-by-Step)
실행 순서: FROM(테이블 로드) → WHERE(개별 행 필터링 ❌ 집계함수 불가) → GROUP BY(그룹핑) → HAVING(그룹 필터링 ⭕ AVG 사용 가능) → SELECT → ORDER BY
⚡ 시험장 1초 컷 공식 (치트키)
WHERE절에 AVG(), SUM(), COUNT() 들어가 있으면 1초 만에 '에러!' 외치고 정답 찍기!
📖 기본 교재 해설 보기 / 접기
WHERE 절에는 집계 함수를 사용할 수 없다.
문제 46번 · NULL 조건 비교 연산자
2과목 SQL 기본 및 활용 · 1장 SQL 기본 · 10번
틀림 NULL/연산
다음 SQL 문장 중 COLUMN1의 값이 NULL이 아닌 경우를 찾아내는 문장으로 가장 적절한 것은? (ANSI 표준 기준)
  • ① SELECT * FROM MYTABLE WHERE COLUMN1 IS NOT NULL;
  • ② SELECT * FROM MYTABLE WHERE COLUMN1 <> NULL;
  • ③ SELECT * FROM MYTABLE WHERE COLUMN1 != NULL;
  • ④ SELECT * FROM MYTABLE WHERE COLUMN1 NOT NULL;
내 선택: ② 정답: ①
💡 개발자 눈높이 해설 (출제자 함정 & 원리)
NULL은 '존재하지 않음 / 알 수 없음(Unknown)'을 뜻하는 특별한 상태값입니다. 따라서 `= NULL`, `!= NULL`, `<> NULL` 같은 일반 비교 연산자를 쓰면 결과가 항상 UNKNOWN(거짓 취급)이 되어 아무 데이터도 조회되지 않습니다. 반드시 `IS NULL` 또는 `IS NOT NULL` 키워드를 써야 합니다.
👶 10살도 이해하는 한 줄 비유
NULL은 비어 있는 투명 상자예요. '상자 안의 비밀 물건 != 상자 안의 비밀 물건'이라고 비교할 수 없어요. 그냥 '상자가 비었니?(IS NULL)', '안 비었니?(IS NOT NULL)'라고 물어봐야 해요.
⚙️ 단계별 실행 과정 (Step-by-Step)
비교 평가: 1) COL1 <> NULL → 결과: UNKNOWN (WHERE절 탈락) 2) COL1 IS NOT NULL → 결과: TRUE/FALSE 정상 판별
⚡ 시험장 1초 컷 공식 (치트키)
NULL 비교는 무조건 `IS NULL` / `IS NOT NULL`! `<> NULL`이나 `!= NULL`은 SQL에서 무조건 꽝!
📖 기본 교재 해설 보기 / 접기
NULL 값을 조건절에서 사용하는 경우 IS NULL, IS NOT NULL이란 키워드를 사용해야 한다.
문제 47번 · NULL의 연산과 집계 특성
2과목 SQL 기본 및 활용 · 1장 SQL 기본 · 11번
모름 NULL/연산
아래에 대한 설명으로 가장 적절한 것은? CREATE TABLE 서비스 ( 서비스번호 VARCHAR2(10) PRIMARY KEY, 서비스명 VARCHAR2(100) NULL, 개시일자 DATE NOT NULL ); [SQL] ㉠ SELECT * FROM 서비스 WHERE 서비스번호 = 1; ㉡ INSERT INTO 서비스 VALUES ('999', '', '2015-11-11'); ㉢ SELECT * FROM 서비스 WHERE 서비스명 = ''; ㉣ SELECT * FROM 서비스 WHERE 서비스명 IS NULL;
  • ① 서비스번호 칼럼의 레코드 중 '001'과 같은 숫자 형식으로 된 레코드가 하나라도 입력되어 있다면 ㉠은 오류 없이 실행된다.
  • ② 오라클에서 ㉡과 같이 데이터를 입력하였을 때, 서비스명 칼럼에 공백문자 데이터가 입력된다.
  • ③ 오라클에서 ㉡과 같이 데이터를 입력하고 ㉢과 같이 조회하였을 때, 데이터는 조회된다.
  • ④ SQL Server에서 ㉡과 같이 데이터를 입력하고 ㉣과 같이 조회하였을 때, 데이터는 조회되지 않는다.
내 선택: 모름 정답: ④
💡 개발자 눈높이 해설 (출제자 함정 & 원리)
1) NULL과의 사칙연산 결과는 무조건 NULL입니다 (`100 + NULL = NULL`). 2) 하지만 `SUM()`, `AVG()` 같은 그룹 집계함수는 **NULL 값을 자동으로 제외하고 계산**합니다. 따라서 `SUM(SAL)`은 NULL이 아닌 사원들의 급여만 더하지만, 개별 행에서 `SAL + COMM`을 하면 COMM이 NULL인 사원은 합계가 NULL이 됩니다.
👶 10살도 이해하는 한 줄 비유
수학 시험에서 한 문제를 아예 안 푼(NULL) 친구와 점수를 더하면 점수를 알 수 없지만(NULL), 선생님이 반 전체 평균을 낼 때는 시험 안 본 친구는 쏙 빼고 나머지 친구들 점수로만 계산해요.
⚙️ 단계별 실행 과정 (Step-by-Step)
예시: 값 [10, 20, NULL] - 10 + NULL = NULL - SUM(COL) = 10 + 20 = 30 (NULL 자동 제외) - AVG(COL) = 30 / 2 = 15 (건수도 2건으로 계산!)
⚡ 시험장 1초 컷 공식 (치트키)
단일행 연산: 값 + NULL = NULL 그룹 집계함수: SUM(COL)은 NULL 무시하고 계산! (단, COUNT(*)만 NULL 포함)
📖 기본 교재 해설 보기 / 접기
① 서비스번호 칼럼의 모든 레코드가 '001'과 같은 숫자형식으로 입력되어 있어야 오류가 발생하지 않는다. ② ㉡과 같이 입력하면 서비스명 칼럼은 오라클에서 NULL로 입력된다. ③ ㉡처럼 입력되어 있을 때 오라클에서 조회하려면 서비스명 IS NULL 조건으로 조회해야 한다. ④ ㉡처럼 입력되어 있을 때 SQL Server에서 조회하려면 서비스명 = '' 로 조회해야 한다.

함수의 실행 결과로 가장 적절하지 않은 것은? (단, A의 아스키코드는 65이다.)

문제 49번 · GROUP BY와 HAVING의 관계
2과목 SQL 기본 및 활용 · 1장 SQL 기본 · 14번
모름 GROUP BY
GROUP BY 절과 HAVING 절에 대한 설명으로 가장 적절한 것은?
  • ① 집계 함수의 통계 정보는 NULL 값을 가진 행을 포함하여 수행한다.
  • ② GROUP BY 절에서는 SELECT 절과 같이 ALIAS 명을 사용할 수 있다.
  • ③ 집계 함수는 WHERE 절에도 올 수 있다.
  • ④ HAVING 절은 일반적으로 GROUP BY 절 뒤에 위치한다.
내 선택: 모름 정답: ④
💡 개발자 눈높이 해설 (출제자 함정 & 원리)
HAVING절은 원칙적으로 GROUP BY절 뒤에서 그룹을 필터링하지만, GROUP BY절 없이도 단독으로 사용될 수 있습니다. 이때는 테이블 전체를 하나의 단일 그룹으로 보고 집계함수 조건을 평가하여 1개의 요약 행을 반환합니다. 또한 HAVING절에는 집계함수뿐만 아니라 GROUP BY에 지정된 컬럼도 조건으로 올 수 있습니다.
👶 10살도 이해하는 한 줄 비유
HAVING은 '그룹 필터'예요. 보통 동아리별로 모아놓고(GROUP BY) '회원 5명 이상인 동아리만 나와(HAVING)' 하지만, 전교생 전체를 한 묶음으로 보고 '전교생 100명 이상이면 합격' 할 수도 있어요.
⚡ 시험장 1초 컷 공식 (치트키)
GROUP BY 없는 HAVING = 테이블 전체를 1개 그룹으로 집계! HAVING절에 집계함수 없이 일반 컬럼만 쓸 수도 있음(단, GROUP BY 대상 컬럼이어야 함)
📖 기본 교재 해설 보기 / 접기
① 집계 함수의 통계 정보는 NULL 값을 가진 행을 제외하고 수행한다. ② GROUP BY 절에서는 SELECT 절과 달리 ALIAS 명을 사용할 수 없다. ③ 집계 함수는 WHERE 절에는 올 수 없다(집계 함수를 쓸 수 있는 GROUP BY 절보다 WHERE 절이 먼저 수행된다).

모름 SQL기본
SQL의 실행 결과로 가장 적절하지 않은 것은?

  • ② LENGTH('KOREAN') = 6
  • ③ DATE_FORMAT('2022-11-02', '%Y-%m-%d') = 2022-11-02
  • ④ SUBSTR('Gangneung Wonju', 8, 4) = 'g Wo'
내 선택: 모름 정답: ④
💡 개발자 눈높이 해설 (출제자 함정 & 원리)
ROWNUM은 조회된 결과에 임시로 1부터 번호를 매기는 가상 컬럼입니다. `WHERE ROWNUM = 1`이나 `WHERE ROWNUM <= 3`은 동작하지만, `WHERE ROWNUM = 2`나 `WHERE ROWNUM > 1`은 절대로 아무 결과도 나오지 않습니다. 1번 행이 채택되어야 2번 번호가 부여되는데, 1번이 탈락하면 다음 행도 영원히 1번이 되어 조건에 안 맞기 때문입니다.
👶 10살도 이해하는 한 줄 비유
줄을 설 때 1등이 서야 2등 표를 주는데, 문지기가 '2등만 들어와'라고 하면 아무도 1등을 못 해서 줄 전체가 입장 불가예요.
⚙️ 단계별 실행 과정 (Step-by-Step)
ROWNUM 동작: 1번째 행 검사: ROWNUM은 1임. 조건이 ROWNUM=2이면 FALSE → 탈락! 2번째 행 검사: 1번째가 탈락했으므로 이 행도 여전히 ROWNUM은 1임. 또 탈락! → 무한 반복 결과 0건
⚡ 시험장 1초 컷 공식 (치트키)

💡 개발자 눈높이 해설 (출제자 함정 & 원리)
LEFT OUTER JOIN에서 **조건이 ON절에 있느냐, WHERE절에 있느냐**는 천지차이입니다. - `ON A.ID = B.ID AND B.STATUS = 'Y'`: B 테이블에서 STATUS='Y'인 것만 조인하고, 매칭 안 되는 A의 모든 행은 NULL로 살아남습니다. - `WHERE B.STATUS = 'Y'`: 조인을 마친 뒤 최종 결과에서 필터링하므로, B가 NULL로 채워졌던 A의 행들이 전부 탈락하여 사실상 **INNER JOIN으로 변질**됩니다!

1) A LEFT JOIN B ON A.ID = B.ID AND B.VAL > 10 ➔ A는 무조건 전건 출력! 2) A LEFT JOIN B ON A.ID = B.ID WHERE B.VAL > 10 ➔ B가 NULL인 행 전부 제거되어 일반 조인과 같아짐!

CROSS JOIN은 일반 집합 연산자의 PRODUCT 개념으로, 테이블 간 JOIN 조건이 없는 경우 생길 수 있는 모든 데이터의 조합이다. 조건절이 없거나 CROSS JOIN 키워드를 사용할 수 있다.

⚙️ 단계별 실행 과정 (Step-by-Step)
오라클: WHERE A.NO = B.NO(+) AND B.FLAG(+) = 'Y' ANSI 변환: FROM A LEFT JOIN B ON A.NO = B.NO AND B.FLAG = 'Y'

문제 80번 · 집합 연산자 규칙
2과목 SQL 기본 및 활용 · 2장 SQL 활용 · 54번
모름 집합연산자
집합 연산자에 대한 설명으로 가장 적절하지 않은 것은?
  • ① UNION 연산자는 합집합 결과에서 중복된 행을 하나의 행으로 만든다.
  • ② UNION ALL 연산자는 집합 간의 결과가 중복되지 않는 경우, UNION과 결과가 동일하다.
  • ③ UNION 연산자를 사용한 SQL은 각각의 집합에 GROUP BY절을 사용할 수 있다.
  • ④ UNION 연산자를 사용한 SQL은 각각의 집합에 ORDER BY절을 사용할 수 있다.
내 선택: 모름 정답: ④
💡 개발자 눈높이 해설 (출제자 함정 & 원리)
집합 연산자를 쓸 때 지켜야 할 규칙: 1) 두 SELECT문의 **컬럼 수와 데이터 타입**이 일치해야 합니다 (컬럼 이름은 달라도 무방, 첫 번째 쿼리의 컬럼명이 최종 헤더가 됨). 2) **ORDER BY 절은 가장 마지막 SELECT문의 끝에만** 단 한 번 올 수 있습니다. 3) UNION은 중복을 제거하기 위해 내부적으로 정렬(Sort)을 수행하므로 UNION ALL보다 느립니다.
👶 10살도 이해하는 한 줄 비유
두 줄을 합쳐서 하나의 줄로 세우려면 키 재는 기준(타입과 칸 수)이 똑같아야 해요. 그리고 맨 마지막에만 '키순으로 정렬!(ORDER BY)' 할 수 있어요.
⚡ 시험장 1초 컷 공식 (치트키)
1) 컬럼 수 & 타입 일치 필수 (이름은 달라도 됨!) 2) ORDER BY는 무조건 맨 끝에 딱 한 번만! 3) 중복 제거 정렬 부하 = UNION > UNION ALL

💡 개발자 눈높이 해설 (출제자 함정 & 원리)
IN과 EXISTS는 서브쿼리의 참/거짓 판별에서 동등하게 치환될 수 있습니다. 단, **NOT IN 서브쿼리 결과에 NULL이 포함되어 있으면 전체 결과가 무조건 공집합(0건)**이 되는 치명적인 함정이 있습니다. 반면 NOT EXISTS는 서브쿼리의 NULL 값에 영향을 받지 않고 안전하게 동작합니다.
👶 10살도 이해하는 한 줄 비유
NOT IN은 '이 중에 아무도 아니어야 해'인데, 범인 목록에 누군지 모르는 투명인간(NULL)이 껴있으면 컴퓨터가 겁을 먹고 아무도 안 골라줘요(0건).
⚙️ 단계별 실행 과정 (Step-by-Step)
NOT IN 연산: COL NOT IN (10, 20, NULL) → COL != 10 AND COL != 20 AND COL != NULL → COL != NULL 은 UNKNOWN! → AND 연산에 UNKNOWN이 들어가면 전체가 FALSE 취급되어 0건 출력!
